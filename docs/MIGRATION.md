# Migrating an existing project

The kit is built to adopt a project that already has a workflow — a scripts
directory, a hand-written state file, a board generated by an old tool. This page
walks through the migration with **P4Deck** as the worked example; substitute your
own paths everywhere else.

The goal is not to move files. The goal is to keep the same guarantees (single
writer, frozen manifests, QA binding, human acceptance) while the commands become
`atk` commands.

## What P4Deck looked like

| Old | New |
|---|---|
| `ForAIDoc/PM/工作流/state.json` and friends | `layout.flowDir` + `paths.*` in `agent-flow.config.json` |
| `scripts/workflow/state.mjs`, `board.mjs`, `evidence.mjs`, … | `atk state`, `atk board`, `atk evidence`, … |
| `ForAIDoc/PM/工作流/角色/{LEAD,FE,BE,QA}.md` | generated from `templates/flow/roles/` |
| `tools/dsh-p4deck-board` | `atk plugin sync` into `config.plugin.dir` |
| `p4deck-manifest-v1` manifests | `batch.manifestTag` (kept for compatibility) |

The `presets/p4deck.json` preset encodes exactly this layout: `LEAD,FE,BE,QA`,
Chinese labels, `ForAIDoc/PM/工作流` as `flowDir`, `artifacts/workflow` as artifact
directory and the existing plugin identity.

## Step 1 — install the toolkit

```bash
npm install --global agent-team-kit      # or use npx / a source checkout
```

Adopt the project from its root. Do not delete the old workflow directory yet.

## Step 2 — scaffold with the matching preset

```bash
cd D:\GitCode\P4Deck
atk init --preset p4deck --project P4Deck --dry-run     # inspect first
atk init --preset p4deck --project P4Deck
```

Useful flags for a project with a custom layout:

```bash
atk init --roles LEAD,FE,BE,QA --language zh-CN --flow-dir ForAIDoc/PM/工作流
atk init --no-plugin          # when you do not want the DSH panel yet
```

`atk init` refuses to overwrite an existing `agent-flow.config.json`; pass
`--force` only when you intentionally regenerate the flow docs.

## Step 3 — review the generated config

Open `agent-flow.config.json` and compare it with the real tree:

- `layout.flowDir` and `paths.*` point at the existing files (`看板.md`,
  `任务单模板.md`, `命令速查.md`, `人类待办.json`, `运行状态.json`).
- `roles` matches your role set (`LEAD,FE,BE,QA` for P4Deck).
- `gates.fast.groups` and `gates.fast.steps` reflect the real checks
  (`format`, `typecheck`, tests, ownership preflight, state check).
- `gates.quick` / `gates.local` point at the real full/heavy commands.
- `batch.manifestTag` is `p4deck-manifest-v1` when old manifests must keep
  working — **do not change it** without a version bump and a migration note.
- `baseline.roots`, `cache.targets`, `rotation` describe the existing directories
  and docs.
- `plugin.id` / `plugin.dir` match the installed DSH plugin (`p4deck-board`,
  `tools/dsh-p4deck-board`).

Run `atk state check` and `atk ownership verify-config` to smoke-test the config
before touching daily work.

## Step 4 — ownership shims

`ownership.json` must express the rules your old workflow enforced. For P4Deck:
`tests/qa/batch-qa/**` and `tests/browser/**` -> QA, `src/**` -> FE,
`src-tauri/**` -> BE, `scripts/**`, `tools/**`, `ForAIDoc/**` and root config ->
LEAD. `atk init` derives a first cut from the visible top-level directories; add
the specific prefixes the old files had, then run:

```bash
atk ownership verify-config
atk ownership map src/features/changelists/action/foo.ts   # spot check
```

Rules are longest-prefix-wins, and one path may only belong to one role.

## Step 5 — command shims

Keep old call sites working while scripts migrate. Create one shim per old entry
point that forwards to `atk`:

```js
#!/usr/bin/env node
// scripts/workflow/state.mjs - compat shim, delegates to the toolkit
import { runCli } from "agent-team-kit";
process.exitCode = await runCli(["state", ...process.argv.slice(2)]);
```

Mapping for the common P4Deck scripts:

| Old script | Shim target |
|---|---|
| `state.mjs check` | `atk state check` |
| `state.mjs board` / `board.mjs` | `atk state board` / `atk board` |
| `state.mjs task <ID>` | `atk state task <ID>` (`atk task <ID>` alias) |
| `state.mjs queue` | `atk state queue` (`atk queue` alias) |
| `evidence.mjs` | `atk evidence` |
| `ownership.mjs` | `atk ownership` |
| `batch.mjs` | `atk batch` |
| `ci-fast.mjs` | `atk gate fast` |
| `sync.mjs` | `atk sync` |
| `archive.mjs` | `atk docs rotate` |

Convenience aliases (`atk task`, `atk queue`, `atk check`, `atk import`,
`atk archive`, `atk restore`) forward to `atk state`; document the canonical form
in your `commands.md`.

## Step 6 — state and evidence

- If you keep the existing `state.json`, run `atk state check --strict` and fix
  any schema drift first. Keep `schemaVersion` consistent with the kit's state
  contract (`1` in this release); old files that carry a different integer are
  preserved by the reader but are not covered by the tested contract.
- If you start a fresh state, let `atk init` write the empty one and migrate
  packages with `atk state import` from the markdown backlog (`paths.todoSource`),
  then re-apply archived/human-accepted flags explicitly.
- Point `layout.evidenceDir` at the durable evidence directory the old tool used
  (`artifacts/evidence` for P4Deck) and run `atk evidence --dry` to see what would
  be derived before it is written.
- Keep the old receipts: the manifest tag and `qa-approval.json` format are
  preserved so `atk batch verify` still understands them.

## Step 7 — board and plugin

```bash
atk board                    # render the static HTML board (atk state board writes board.md)
atk serve                    # live board on board.port
atk plugin sync              # refresh tools/dsh-p4deck-board with this project's identity
atk plugin verify
```

Then install/enable the plugin in DSH, merge the generated `cordis.patch.yml`
`insert:` block into `~/.dsh/profiles/<profile>/cordis.patch.yml`, and **restart
DSH** — the plugin tree and client bundle are built at startup. If the old plugin
was installed under a different id, remove the old row from the profile patch
first so two boards do not claim the same route.

## Step 8 — verify and freeze the old tooling

1. `atk state check --strict`, `atk ownership verify-config`, `atk board`.
2. Take one small task through the new loop end to end (ticket -> freeze -> QA ->
   verify -> apply -> evidence) in a scratch branch.
3. Compare the old board output with the new one; they may differ in labels, not
   in facts.
4. Only then move the old scripts to an `archive/` directory (or delete them) and
   make the shims the only entry points.

## Rollback

The migration writes new files and a plugin copy; it does not modify product code.
To roll back: delete `agent-flow.config.json`, the generated flow files and the
plugin copy, then re-run the old scripts (which were never deleted during the
transition). Keep the old workflow directory untouched until step 8 passes.

## Checklist

- [ ] `agent-flow.config.json` matches the real layout and commands.
- [ ] `atk state check --strict` passes.
- [ ] `atk ownership verify-config` has no conflicts or unused roles.
- [ ] One synthetic task completed end to end with evidence.
- [ ] Board renders and the DSH panel appears after a restart.
- [ ] Old scripts either shimmed or archived; no two tools write the same state.
- [ ] `batch.manifestTag` unchanged if old manifests must stay verifiable.
