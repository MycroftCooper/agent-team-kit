## 关键缺陷（均由门禁/QA 撞出，非"实现自检"）

1. **F01 缺口（BLOCKER 级）**：通用 PATCH 可直推 6 个执行态 → 双层守卫（REST + store），6 条边全部 409 `execution-state-guard`，零写入。
2. **F06 自审绕过（BLOCKER 级）**：`body.actor` 声明任意 reviewer 即可 PASS → 身份改为 assignment + 内部凭据角色；Run 绑定校验（`runId` 的 agent 必须等于 assignment reviewer）；自审判定取 **review.runId 的 producer**（而非最新 active Run，该 bug 曾把合法 reviewer 误判为自审）。
3. **F03 部分提交（MAJOR）**：批次中途失败留下半完成状态 → `applyRuntimeEventBatch` 单事务，失败抛 StoreError 整体回滚；跳步仍 400。
4. **F08 事件丢失（MAJOR）**：同毫秒多事件被旧复合键折叠 → `eventId` 唯一键 + 迁移 0006；100 条同毫秒事件全保留，三重放只 1 份。
5. **F02 结果丢失（MAJOR）**：上报失败即清本地记录 → FINISHING + 持久 Outbox，未 ack 不算成功；重试同 idempotencyKey；cap 后 MANUAL_REQUIRED。
6. **F07 失权未撤停（MAJOR）**：STALE 只记日志 → 等待 runtime.stop，失败进 FENCING_REQUIRED，不盲目领取。
7. **F09 恢复误判（MAJOR）**：损坏记录当空数组 → RECOVERY_REQUIRED，保留损坏文件，原子写 + `.bak`。
8. **QA-M61-01（MINOR）**：共享路径规则接受 `C:\abs` → contracts 拒绝盘符，与 legacy importer 一致。
9. **m2-smoke 撞出的契约错误**：我最初写"批次最多一条 run.updated"，会让真实 Host 的正常完成被 400 → 契约放宽为多条顺序应用（跳步仍 400）。
