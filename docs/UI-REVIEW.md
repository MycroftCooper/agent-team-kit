# Multica 桌面 UI：哪些设计适合 Agent Team Kit

对照基于本机 HG Multica 桌面端实际界面、安装包和 [Multica 的任务文档](https://multica.ai/docs/issues)。前一轮静态检查的安装包为 1.3.1，本轮查看界面时本机可执行文件版本为 1.4.1。观察范围是工作区导航、任务详情和智能体列表。

**最好的一点是同屏有三个层级。** 左边的工作区与视图告诉你在哪里；中间的任务标题、正文和活动说明发生了什么；右边的状态、负责人、项目和优先级补充背景。标题足够醒目，普通信息靠字号、留白和分隔线组织，颜色主要用于状态和交互。ATK 原先把正文、属性、锁和执行记录堆进同一个居中弹窗，查看记录时也会遮住任务列表。这次改成右侧详情面板，正文和交付历史放主栏，角色、评审和文件范围放属性栏；窄屏按阅读顺序叠放。

**列表服务于下一步操作。** Multica 把筛选和排序放在列表旁，智能体状态与最近活跃分列，一眼就能区分身份存在和机器近期有联系。ATK 将「待我处理」提到侧栏靠前位置，减少重复的标题与介绍。任务详情把依赖、文件占用、身份与并发容量翻成原因和下一步；接入面板将验证凭据、登记联系、开始领取分成三步。联系状态是观测，仍由外部 Agent 主动领任务。

**一条任务是交付入口。** Multica 将评论、状态变化和执行活动放回任务。ATK 在同一处提供计划任务、执行代次与最终验收；打开某次运行后，可以查看该代次的检查日志、快照或独立评审。可复制的链接只带项目和目标 ID。审批与评审仍按现有的计划版本和证据校验执行。

**看板要能改变观察角度。** Multica 的任务视图复用同一批任务，可以按状态或负责人等属性分组。ATK 提供「按流程」和「按执行方」两个入口。前者用于看交付走到了哪一步，后者用于看人和 Agent 分别需要做什么。卡片从上到下显示任务类型、标题、所属需求、状态或等待原因、执行者与可用动作。列计数基于整个工作空间，各列单独分页；搜索和执行方筛选也作用于整个工作空间。

**人和 Agent 共用交付流程，各自有合适的操作。** 人工任务能从卡片开始和提交，Agent 卡片可以指定符合批准角色的具体身份。Multica 指派 Agent 会进入它的运行队列；ATK 把指派作为领取资格，依旧由外部 Agent 主动领取。依赖、并发、文件锁和独立评审不变；被撤销的指派需要由人清除或改派，其他 Agent 不会自动接手。

**显示设置放在同一个入口。** 任务页的「显示」在看板、列表、表格和泳道间切换。泳道用同一套流程列对齐人工、Agent 和需求；表格方便比较状态、执行者、优先级和更新时间。排序和子任务开关作用于整个筛选结果，再按列或页面分页。列和卡片属性可单独显示；子任务进度统计当前计划中已验证或已完成的任务。显示偏好保存在本机浏览器，不更改任务记录。
