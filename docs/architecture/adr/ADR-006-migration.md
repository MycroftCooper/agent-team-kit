# ADR-006：迁移分三阶段——JSON 兼容只读 → 停机切换 → SQLite 唯一真值

- 状态：**Proposed**
- 日期：2026-11-02
- 决策者：ARCH
- 关联：规范 §13、§1.2 第 6 条、§14（ATK-105）；ADR-002

## 背景

v0.2.0 的 `state.json` 是唯一事实来源，且已有真实项目在用（本仓库自我托管、`examples/minimal`、P4Deck 等）。直接切 SQLite 会造成两类事故：双写漂移；以及在迁移失败时丢失事实源。规范还明确要求：**不得以 `atk init --force` 作为迁移工具**（它会覆盖已生成的状态/角色卡）。

## 决策

迁移显式分成三个阶段，每个阶段有独立的准入与回滚点：

### A. 兼容只读期
- 旧 `lib/` CLI 与 `state.json` 仍是真值。
- 新 Backend/Web 只**读**（通过适配层读取 JSON），**禁止双写**。
- 此阶段不得出现“Web 写、CLI 也写”的任何路径。

### B. 停机切换期
1. 对项目工作流文件做完整备份（含 `state.json` / `ownership.json` / `runtime.json` / 证据目录索引）；
2. 阻止旧写入口（`atk state`/`init`/`batch apply` 在迁移锁存在时拒绝写入）；
3. `atk migrate --dry-run`：只校验不写，输出记录数、字段完整性、引用关系、重复 ID、跨版本配置差异；
4. 消除冲突后正式 `atk migrate`；
5. 写入迁移 manifest（源文件 hash、记录数、时间、工具版本、schema 版本）。

### C. SQLite 运行期
- Backend 是唯一真值；旧 `state.json` 降级为备份/导入导出格式。
- 旧 CLI 命令改为调用 Backend/API 或受控 `atk export`。
- 必须长期提供 `atk export`（SQLite → 旧 JSON）与迁移失败回滚流程。

## 迁移验收样本（必须全部覆盖）

已归档 Task、人工验收记录、QA 回执、子任务、历史批次、**非 ASCII 路径**（本机用户目录含中文，必须专门测）、无效/缺字段记录、重复 ID、跨版本配置（schemaVersion 缺失与未知）。

## 理由

- 三阶段把“读写所有权”与“数据格式”解耦：先解决读，再解决写，最后才切换真值，每步都能停。
- 只读期可以长时间存在，允许 Web 先上线而不冒险。
- 显式 `migrate` 命令替代 `init --force`，把“覆盖”这个危险动作从常规路径里移除。

## 后果

**正面**：迁移可 dry-run、可核对、可回滚；旧项目不必一次性冒险；非 ASCII/脏数据在 dry-run 就暴露。

**负面 / 代价**：三阶段期间要维护两套读取路径；只读期用户可能困惑“为什么 Web 上改了不生效”（必须显式标注只读）。

**缓解**：只读期在 UI 与 CLI 输出明确标注 `read-only compatibility mode`；`migrate --dry-run` 报告作为切换门禁。

## 替代方案

| 方案 | 为什么否决 |
|---|---|
| `init --force` 重新生成再导入 | 覆盖用户既有状态与角色卡，不可回滚；规范明令禁止 |
| 直接双写过渡 | 必然漂移，且无法判定哪边是真值 |
| 一次性硬切 | 失败即丢事实源，违反 §0 第 9 条“可回滚” |

## 兼容与迁移

M1（ATK-105）实现 `migrate` 与 `export`；在 `dry-run` 报告里固化上面 9 类样本的检查项。样本库放在 `tests/failure/` 与 `tests/integration/`（M1 建立）。

## 回滚

保留迁移前完整备份与迁移 manifest；回滚 = 恢复备份文件 + 删除新 DB + 重新进入 A 阶段。因为没有双写，回滚不会丢数据。
