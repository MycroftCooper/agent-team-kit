# ADR-008：本地访问安全——loopback + Host/Origin + CSRF + 内部凭据

- 状态：**Proposed**
- 日期：2026-11-02
- 决策者：ARCH
- 关联：规范 §2.1、§7.2、§12.1；ADR-001、ADR-007

## 背景

ATK 在 `127.0.0.1:1421` 上跑一个有写能力的 HTTP 服务，并且浏览器会访问它。常见误解是“绑定 loopback 就安全”。实际上至少有三类本地攻击面：

1. **DNS Rebinding**：攻击者域名解析到 `127.0.0.1`，让浏览器把恶意页面的请求发到本机服务；
2. **CSRF**：任意网页可以向 `127.0.0.1` 发简单请求，若服务按 Cookie/会话自动授权就被越权；
3. **任意进程直连**：本机其它进程可以不带 Origin 直接打内部端点。

同时规范要求内部 API（Scheduler/Runtime 使用）绝不能暴露给任意网页。

## 决策

1. **绑定地址固定 `127.0.0.1`**（不接受 `0.0.0.0`、不做局域网访问）。
2. **强制校验 `Host`**：只接受 `127.0.0.1[:port]` / `localhost[:port]` / `[::1]`，其余一律 403（防 DNS Rebinding）。
3. **状态变更请求强制校验 `Origin`**：必须是同源；无 `Origin` 的非 GET 请求同样拒绝（curl/CLI 走**显式令牌**而不是绕过校验）。
4. **会话令牌 + CSRF token 双因子**：页面启动时由 Backend 下发短期会话令牌（仅存内存/安全存储，不长期落盘）；写请求必须带 CSRF token。GET 只读也要求会话令牌。
5. **内部 API 与浏览器会话彻底分离**：`/internal/v1/*` 使用独立的、短期、进程启动时生成的凭据（`scheduler`/`runtime` 各一份），并校验显式 actor 头；**绝不接受浏览器同源会话令牌调用内部 API**。后续可换 Windows Named Pipe（同机、无端口）。
6. **命令执行只用 argv 数组**，不拼接用户可控字符串到 shell；对工作目录做根路径、符号链接、UNC 路径检查（防越界与 UNC 凭据泄露）。
7. **子进程环境最小化**：只继承必需变量；凭据不落日志；日志脱敏；`kill`/`delete`/`force-reset`/`publish`/`merge-protected` 需要专门授权并写审计。
8. **默认不读写用户模型网关配置**（与 ADR-004 一致），`doctor` 也只读。

## 理由

- 四层校验（绑定地址 → Host → Origin/CSRF → 会话与内部凭据）逐层独立，任何一层失效仍有下一层。
- 内部凭据与外部会话分离，是“内部 API 不得暴露给任意网页”唯一可验证的实现方式。
- argv 数组执行消除注入面；路径检查防 UNC/符号链接把写入引到仓库外。

## 后果

**正面**：本地服务具备可证明的访问边界；CLI/插件必须显式带令牌，行为可审计；内部接口不受浏览器侧漏洞影响。

**负面 / 代价**：CLI 与插件需要先取令牌；调试 curl 时多一步；Named Pipe 迁移要改客户端。

**缓解**：`atk` CLI 用本机凭据文件（权限收紧的用户态目录）自动换取短期令牌；`atk doctor` 输出当前安全配置摘要；文档给出带令牌的调用示例。

## 替代方案

| 方案 | 为什么否决 |
|---|---|
| 只靠 loopback 绑定 | DNS Rebinding 与 CSRF 都不需要跨网即可利用 |
| 只校验 Origin | 非浏览器进程不带 Origin；且 GET 型副作用仍需防 |
| 用 Basic Auth + 弱口令 | 密码会被本地其它进程读取；不如进程内短期凭据 |
| 关掉认证只跑在“内部” | 一旦浏览器打开页面即暴露，规范明令要求认证 |

## 兼容与迁移

M1（ATK-102）实现 HTTP 层与校验中间件；M3/M2 接入内部凭据。既有 CLI 命令不经过 HTTP，不受影响。

## 回滚

安全中间件集中在 Backend 的单一 hook 里，可单独关闭某一层做诊断，但**默认值必须是开启**；关闭状态必须在 `health` 与 `doctor` 里显著标注。
