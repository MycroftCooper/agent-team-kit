# M6.3 契约冻结（二次审查 P0/P1 修复）

- 基线 `c20513c` · 分支 `fix/m6.1-runtime-reliability`
- 原则：先核查（有防护就给证据）→ 红测试 → 修复 → 独立 QA；不重构架构
- 本文件是五个工作包的共同依据；形状变更先改这里

## 1. P0-1 心跳协议（Runtime ↔ Backend ↔ Scheduler）

- Host → `POST /internal/v1/runtime/heartbeat`，body **只** `{ hostId, agentIds, capacity }`（旧 `{ownerId,status,capabilities,sessions}` 移除）。
- 响应 `{ at, hostId, capacity, agents: [{ agentId, available, reason }] }`。
- Host 启动后立即发一次，之后每 `heartbeatMs`；**连续 2 次失败 → 停止 claim**（`HEARTBEAT_LOST`，不静默继续领活）。
- Scheduler 只依赖 `agentAvailability`（心跳 TTL 内 + capacity>0）派工；这条链路必须有真实 launcher 多进程测试。

## 2. P0-2 角色独立凭据

- Backend 启动时生成**两枚互不通用**的内部 token：`scheduler` 与 `runtime-host`；`ATK_INTERNAL_TOKEN` 仍是环境变量名，但**每个子进程拿到不同值**（launcher 从 backend 一次性读取后分别注入）。
- 服务端把 token→role 绑定在启动时确定；请求头 `x-atk-internal-role` 若出现**必须等于 token 绑定角色**，否则 403 `internal-role-forbidden`；**不再仅凭 header 声明角色**。
- Human Approval：只接受浏览器 session + CSRF；任何内部 token 调用 decide → 403 `human-approval-requires-session`。
- Agent 子进程**不得继承**内部 token（Host 启动子进程时显式剥离）；Host 进程内保留自身 token 用于 events/result。
- 最小权限：`scheduler` token 可 snapshot/claim/sweep/availability/integration；`runtime-host` token 可 events/result/renew/reconcile/spec/heartbeat；交叉调用 403。

## 3. P0-3 Worktree 分支拆分

- `runs.work_branch`（migration 0008，**UNIQUE**，默认 `atk/run/<runId>`）；`runs.target_branch` = **集成目标**（如 `dev`/`main`），不再用作 worktree 分支。
- `packages/workspace.ensureWorktree({ workBranch, targetBranch, baseCommit, worktreePath })`：worktree 只 checkout/attach `workBranch`；`targetBranch` 仅记录为集成元数据。
- 同一 project 下多个 Run 可共享 `targetBranch`，各自 `workBranch` 不同 → 并行互不冲突。

## 4. P0-4 Outbox 对账绑定

- `GET /internal/v1/runs/:id/reconcile` 响应增加：
  `command: { id, generation, status, result, eventId } | null`，以及 `pendingResult`（若存在）。
- Host 清 Outbox 的条件（全部满足）：`command` 存在、`command.status` 终态（DONE/FAILED）、`command.generation === outbox.generation`、`command.result.eventId === outbox.eventId`（或 `command.result.idempotencyKey` 匹配）、Run 终态。
- 任一不满足 → **保留 Outbox** 并继续重试；**禁止仅凭 Run 终态清 Outbox**。

## 5. P1-5 eventId 贯通 Host

- Host 为每条 Runtime 原始事件生成 `eventId`（UUID v4）与 `sessionSeq`（每 session 单调递增）；重试复用相同 `eventId`。
- 批次携带 eventId/sessionSeq；同毫秒多事件、跨批次重试、断线重连后都不得重复或丢失。

## 6. P1-6 停止与租约撤销

- `runtime.stop()` 抛错 → 进 `FENCING_REQUIRED`；不得报告"已安全停止"。
- `host.stop()` 必须尝试停止所有会话并聚合结果：`{ stopped: string[], failed: {sessionId,error}[], fencingRequired: boolean }`；任一失败 → `fencingRequired:true`，且**不得释放冲突写域**、不得允许新 claim。

## 7. P1-7 恢复文件原子性

- 禁止 `copyFileSync` 覆盖回退。写入策略：`tmp` → fsync → `rename`；`rename` 在 Windows 被占用时**重试+退避**，仍失败则写 `*.next` 并在启动时选择最高有效代；**始终保证至少一份完整可读状态**，否则 `RECOVERY_REQUIRED`。
- 必须断电/中断模拟测试（写到一半崩溃 → 启动后读到上一份完整状态）。

## 8. P1-8 Reviewer Run 身份

- `reviews.reviewer_run_id`（0008）；`createReview` 必须绑定 reviewer Run。
- `submitReview` 校验：`review.reviewer_run_id` 对应 Run 的 `function === "REVIEWER"`、`taskId === review.taskId`、`agentId === reviewer_agent_id`；任一不符 → 403 `REVIEW_RUN_NOT_REVIEWER`。
- 普通 WORKER Run 不能作为可信审查凭据。

## 9. P1-9 禁止真实执行回退主工作区

- 真实执行要求 `workspace.kind === "worktree"`；`none` 仅允许显式测试/Mock：Host 要求 `ATK_ALLOW_NONE_WORKSPACE=1` 且 runtime 为 mock，否则拒绝 `WORKSPACE_REQUIRED`。
- Backend 对真实任务派发 `none` → 400 `workspace-required`。

## 10. P2-10 边界与文档

- `scripts/check-boundaries.mjs` 纳入 `runtime-host`，允许 `{contracts, workspace, runtime-sdk}`；Host 改用包名 import + package.json 依赖（不再相对路径跨包）。
- 完成后更新 README / V1-READINESS / 运维文档 / schema 说明；**不进入 M7**。

## 验收

真实 Launcher 多进程：两个独立任务自动派发 → 各自 worktree → 冻结 spec → 事件/结果可靠落库 → 故障注入（断网/超时/崩溃/ACK 丢失/租约失效/停止失败）→ 无重复执行、无错误成功、无丢失证据、无越权审批 → 重启恢复或明确 `RECOVERY_REQUIRED` → 独立 QA 签字。

## 11. migration 0008 冻结形状（阶段 A 核查后定稿）

- `runs.work_branch TEXT NOT NULL`；唯一性 `UNIQUE(project_id, work_branch)`（同一项目内分支名唯一；跨项目互不影响）。`claimTask({ workBranch? })` 缺省 `atk/run/<runId>`；`createRun`/`runJson` 返回 `workBranch`；`targetBranch` 仅作集成目标写入 `runs.target_branch`。
- `dispatch_commands.event_id TEXT`（可空）：`completeDispatchCommand` 记录 result.eventId；`reconcileRun` 返回
  `command: { id, generation, status, result, idempotencyKey, eventId } | null`。
- `reviews.reviewer_run_id TEXT`：`createReview` 在 `assignedTo==="AGENT"` 时**必须**传 `reviewerRunId`（缺失 → `VALIDATION_ERROR`，`details.field="reviewerRunId"`）；`submitReview` 要求该 Run：`function==="REVIEWER"`、`taskId===review.taskId`、`agentId===reviewer_agent_id`；任一不符 → `REVIEW_RUN_NOT_REVIEWER`（store 抛 → HTTP 403）。
- `events.legacy INTEGER NOT NULL DEFAULT 0`：迁移时回填 `event_id IS NULL` 的旧行为 `1`；读取时仍输出 `legacy:true`（保持兼容），但以列为准。
- `WORKSPACE_REQUIRED`（400）与 `REVIEW_RUN_NOT_REVIEWER`（403）已加入 `@atk/contracts` 的 `ERROR_CODES`。
